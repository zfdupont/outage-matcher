Scope: M1 only (ingest, chunk, embed, index, search CLI). The agent graph, tool-use loop and citation checks do not exist yet and are out of scope for this round. commands.md is at HEAD 147b7a5, which matches the worktree, so I did not rerun the commands. All three pass (40 passed, ruff clean, format clean). I ran small probes against the chunker and the live index.

1. src/outage_matcher/ingest/chunk.py:141 (`MIN_BODY_CHARS`): chunking drops text. Any section whose body is under 40 chars is discarded, heading included. Short Impact and Fix sections are the useful ones. I probed `<h2>Impact</h2><p>Users saw 5xx for 12 minutes.</p>` and `<h2>Fix</h2><p>Rolled back the change.</p>`. Both vanished, and only the Summary and Root cause chunks came out. Fix: do not drop non-empty sections. Merge a short section into the previous or next section (keeping its heading line in the text), or keep it as its own chunk. Only discard sections with no body at all. Add a test with a short Impact section that asserts its text is present in the chunks.

2. src/outage_matcher/ingest/chunk.py:113-131: text outside block tags is silently lost when block tags cover 50% or more of the page text. The fallback at line 132 only triggers below 50%. Probe: a page with a 700-char `<p>` and a long text-bearing `<div>` with no `<p>` produced one chunk, and the div text was gone. Across data/raw, 2 of the 235 documents keep less than 80% of the main-container text (about 70% and 77%). Fix: also collect direct text nodes and anonymous text in non-block containers, for example by treating `div` and `section` leaves with no block descendants as blocks (add them to the block-tag handling). Add a fixture test for it.

3. src/outage_matcher/search.py:45-50: `k` larger than `hnsw.ef_search` (default 40) is silently truncated, because the query goes through the HNSW index. I ran it against the live index with 4092 chunks: `search(..., "bge", k=100)` returned 40 rows, while k=10000 returned 4092. The result depends on the planner. The `--system-type` filter is applied after the index scan, so rare labels can also return fewer than k rows. Fix: inside a transaction, run `SET LOCAL hnsw.ef_search = max(k, 40)` (the cap is 1000, so also reject or clamp k above that). When `system_type` is set, also `SET LOCAL hnsw.iterative_scan = relaxed_order` (pgvector 0.8.7 is installed). Add a `db`-marked test that k=100 returns 100 rows.

4. src/outage_matcher/ingest/index.py:67-77: `write_index` always runs `TRUNCATE chunks, postmortems`, even when `docs` is empty. `outage-matcher ingest --skip-collect` with a manifest but no `data/raw` files (a fresh clone, because raw is git-ignored) makes every entry a "raw file missing" failure. The command then wipes the live index to zero rows, overwrites `data/corpus_stats.json` with zeros, and exits 0. Fix: in `write_index`, or in `cmd_ingest` before connecting, raise or return non-zero when `docs` is empty. Add a test that checks the index is left untouched in that case.

5. src/outage_matcher/cli.py:43-54 and src/outage_matcher/db.py:69: `search --k 0` (or a negative k) escapes as a raw `ValueError` traceback from `search()`. An unreachable database escapes as a raw `psycopg.OperationalError` traceback. The task asks for failures that surface as clear errors. Fix: validate k with an argparse type (positive int). In `main()`, catch `psycopg.OperationalError` and `RuntimeError` (the missing `DATABASE_URL` case) and print a one-line message to stderr with exit code 1. Add a test for each.

6. src/outage_matcher/ingest/collect.py:326, 418 and 360: failure handling in collection is partial. Only `httpx.HTTPError` is caught. `httpx.InvalidURL` is not an `HTTPError`, so one malformed URL in the community list aborts the whole `collect` run. The manifest is written only at the end (line 511), so that abort loses all progress. In `index_links` (line 360), a network failure or a non-200 response is swallowed with `break` and only shows up as fewer candidates, with no log line. Fix: catch `(httpx.HTTPError, httpx.InvalidURL)` in `fetch_one` and `_load_robots`. Log index-page failures through the existing `log`. Optionally write the manifest in a `finally` block. The 20s client timeout is fine.

Non-blocking notes:
- No embedding model name or dimension is stored with the index. `search` picks the column from the model key, so a key-to-model change in `MODELS` would silently query mismatched vectors (both models are 384-dim). `embed_query` output is not checked against `EMBEDDING_DIM`. Consider storing the model ids in a small `index_meta` table and failing on a mismatch before M2 builds on this.
- The 1000-char cap does not hold once the heading is prepended (`chunk_sections`, line 188). I probed chunks of 1176 chars. MiniLM truncation is the reason for the cap, so consider budgeting the heading length.
- A parent heading with no body (an h2 followed straight by h3s) is dropped, and its children are typed `other` with no parent context.
- Empty index and unknown model are handled: the CLI prints "no results", and `search` raises a clear `ValueError` for an unknown model. Tests use fakes, and the network and Postgres tests are marked and deselected. Both of these are fine.
