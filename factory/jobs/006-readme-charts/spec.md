# README charts drawn from the recorded eval results

## Goal
Add three matplotlib figures to the README Results section, generated by a new module
`outage_matcher.evals.charts` that reads only the committed files in `evals/results/` through the
loaders `summary.py` already has. No new measurement, no API call, no hand-typed metric: every
plotted value is a field of a result file, so the hard rule "Every number in the README must come
from a recorded run" is kept, not weakened. `summary.py`, `evals/results/summary.md` and
`evals/baseline.json` do not change.

## Behavior

Command (from the repo root, like `summary`):

    uv run python -m outage_matcher.evals.charts [--results-dir DIR] [--out-dir DIR]

Defaults: `--results-dir evals/results`, `--out-dir docs/img`. It creates the output directory if
needed, writes three PNGs, prints one line and exits 0:

    wrote docs/img/retrieval-metrics.png, docs/img/faithfulness-before-after.png, docs/img/rank-change-rerank.png

Errors follow `summary`: `error: <message>` on stderr, exit 1, and no file is written (all three
figures are built before any is saved). Cases:

- result files differ in gold set or index version: the `ValueError` of `summary.check_comparable`
  (retrieval runs, `faithfulness.json` and the earlier faithfulness runs checked together)
- no section-chunking run without a reranker: the `ValueError` of `summary.pick_baseline`
- `faithfulness.json` is missing, or none of `summary.EARLIER_FAITHFULNESS_FILES` exists
- there is not exactly one run with a reranker and the baseline's embedding model and chunking
- a faithfulness run's `metrics.queries` differs from `gold.queries` (a `--limit` run would make
  the n in the title false)

The figures (n below is `gold.queries` read from the files, 34 today; never a literal):

1. `retrieval-metrics.png`: grouped bars. Five groups on the x axis in `summary.METRIC_KEYS` order
   (recall@1, recall@3, recall@5, recall@10, MRR), one bar per retrieval run in each group. Run
   order: section chunking without a reranker first, then the rest, each in `load_runs` order (today:
   bge section, minilm section, bge neighbor, bge + rerank). Legend labels are
   `summary.config_label(run)`. Bar height is `run.metrics[key]`, unrounded. Y axis fixed at 0 to 1.
   Title contains `n=34 synthetic queries`.
2. `faithfulness-before-after.png`: two panels sharing the x axis categories, one per run: every
   earlier run that `load_earlier_faithfulness` returns, oldest first, then `faithfulness.json`.
   Tick labels are the run names of the summary table (`before the fix, first run`,
   `before the fix, second run`, `after the fix`; a line break inside a label is fine). Left panel:
   stacked bars of `metrics.answered_and_judged` (label `answers judged`) and `metrics.no_match`
   (label `abstained`), y axis in gold queries; a third `errors` segment only if any run has
   `metrics.errors` above 0. Right panel: one bar per run of `metrics.claim_support_rate`, y axis
   fixed at 0 to 1, y label saying the rate covers judged answers only; a run whose rate is null
   gets no bar. The figure title contains `n=34 synthetic queries` and
   `single nondeterministic run`.
3. `rank-change-rerank.png`: paired dot plot, one row per gold query (y tick label is the query
   id), x axis is the rank of the source document: positions 1 to 10, then one more position
   labeled `not in top 10` for any rank above 10 or null. Each row has a baseline marker and a
   reranked marker (different color and different marker shape), joined by a thin gray line when
   they differ. Rows sorted by baseline position, then reranked position, then id. Baseline is
   `summary.pick_baseline(runs)`; ranks are `Run.ranks`. Legend labels are `config_label` of the
   two runs. Title contains `n=34 synthetic queries`.

All figures: white figure and axes background, saved opaque at dpi 150, colors only from the
Okabe-Ito colorblind-safe palette (plus gray and black for lines and text), non-empty x and y
labels on every axes, a legend wherever there is more than one series, ASCII-only text (no emojis,
no em-dashes), and no numeric annotations on bars or markers (the tables carry the exact values).
Each PNG is under 150 KB.

## Design

- `pyproject.toml`, `uv.lock`: `uv add --dev matplotlib` (dev group only; the Docker image installs
  with `--no-dev` and is unaffected). `requirements-dev.txt`: add `matplotlib` (milestones
  convention: keep it in sync).
- New `src/outage_matcher/evals/charts.py`, same shape as `summary.py` (module docstring with the
  command, `main(argv) -> int`, `if __name__ == "__main__": raise SystemExit(main())`):
  - Imports from `summary`: `Run`, `load_runs`, `load_earlier_faithfulness`, `check_comparable`,
    `pick_baseline`, `config_label`, `METRIC_KEYS`; `RESULTS_DIR` from `run_retrieval`. It does not
    open result files itself and does not call `metrics.compute_metrics`.
  - Constants: `IMG_DIR = Path("docs/img")`, `DPI = 150`, `RANK_CAP = 10`, `PALETTE` (Okabe-Ito hex
    colors), the three file names.
  - `binned_rank(rank: int | None, cap: int = RANK_CAP) -> int`: the rank if it is at most `cap`,
    else `cap + 1`.
  - `retrieval_figure(runs) -> Figure`: bars drawn with one `Axes.bar` call per run, so
    `fig.axes[0].containers[i]` is run i with label `config_label(run)` and five patches in
    `METRIC_KEYS` order.
  - `faithfulness_figure(earlier, now) -> Figure`: `fig.axes[0]` is the stacked count panel (one
    `Axes.bar` call per segment, labelled as above), `fig.axes[1]` the rate panel.
  - `rank_change_figure(base, other) -> Figure`: one `Axes.scatter` call per series, labelled with
    the config label, x offsets are the binned positions, row i at y = i.
  - `build_figures(results_dir) -> dict[str, Figure]`: load, `check_comparable`, the checks listed
    under Behavior (raising `ValueError`), return file name to figure. `main` saves them with
    `fig.savefig(path, dpi=DPI)`.
  - Use `matplotlib.figure.Figure(figsize=..., layout="constrained")` directly, not `pyplot` (no
    GUI backend, no global figure state in tests) and no `bbox_inches="tight"`. Suggested sizes in
    inches: 8 x 4.5, 9 x 4, 7 x 8.
  - Only `charts.py` imports matplotlib; nothing imports `charts` (not `evals/__init__.py`, not
    `cli.py`), so the runtime package still works without it.
- `summary.py` is not edited. The three run names for figure 2 are a small tuple in `charts.py`,
  sliced with `[-len(earlier):]` as `summary._render_earlier` does.
- New `tests/test_evals_charts.py`. Tests that use the recorded files read
  `Path(__file__).resolve().parent.parent / "evals" / "results"` as `tests/test_evals_gate.py`
  does; expected values are parsed from the committed `evals/results/summary.md`. Fixture tests
  write small result files to `tmp_path` in the shape `tests/test_evals_summary.py` builds. PNG
  checks use Pillow (already installed with matplotlib).
- Run the command once and commit `docs/img/retrieval-metrics.png`,
  `docs/img/faithfulness-before-after.png`, `docs/img/rank-change-rerank.png`.
- `README.md`: the additions under Behavior. `CLAUDE.md`: a Commands line
  `uv run python -m outage_matcher.evals.charts` - write the README figures to `docs/img/` from the
  result files (matplotlib is a dev dependency; rerun after `summary` when a result file changes);
  add `charts.py` to the evals list in Architecture.
- Commits: brief messages, no Co-Authored-By lines.

## Out of scope
- New eval runs, new metrics, API calls, or any change to `evals/results/*.json`, `evals/results/summary.md`, `evals/baseline.json`, `evals/gold.jsonl`.
- Any edit to `summary.py`, including refactors, and any edit to existing README numbers, tables or prose.
- Figures in `summary.md`, a CLI subcommand, a thin script under `evals/`, CI workflow changes (`.github/**` is untouched), SVG output, dark-mode variants.
- A check that the committed PNGs are current with the result files (rendering is not byte-stable across platforms); the CLAUDE.md line says to rerun the command when a result file changes.
- Error bars or repeated faithfulness runs (backlog item from job 004).
