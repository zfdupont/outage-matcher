1. `.github/workflows/eval.yml:111-112, 125, 170-173`. Owner decision. On a same-repo PR, the faithfulness job runs PR-branch code (the ingest and `run_faithfulness` modules and the lockfile deps) with the real keys in the environment, and spends credits on every push. GitHub uses the PR's own copy of the workflow, so anyone with write access can exfiltrate the keys by editing the workflow. This is inherent to the spec's "secret present" trigger. If you want a hard boundary, put the secrets in a GitHub Environment with a required reviewer and add `environment:` to the faithfulness job, or limit the paid run to `workflow_dispatch`. Dependabot PRs get no secrets, so they are skipped safely.
2. `.github/workflows/eval.yml:67-69, 158-160`. `fetch-raw` exits 0 on partial failure. If a transient network error loses a few pages, the gate can still pass (within the 2 percent count rule and the metric tolerance). `actions/cache` then saves the incomplete `data/raw` under the manifest hash, and later runs get a cache hit and never retry the fetch. Suggested fix: run `fetch-raw --strict` in CI so a partial fetch fails before the cache is saved. The cost is that a flaky page fails the job and needs a rerun.
