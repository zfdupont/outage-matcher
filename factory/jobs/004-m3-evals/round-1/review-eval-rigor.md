What I checked and how

1. Held-out exclusion, all retrieval paths. Every run goes through `Retriever.chunk_order` (src/outage_matcher/evals/retrieval.py:113-130), which sets `sims[excluded] = -inf` and cuts the order to `len(sims) - len(excluded)` before the rerank head/tail split. The reranker therefore never sees or returns a held-out chunk. `Corpus.excluded_indices` (retrieval.py:41-45) raises if the gold ords no longer exist, so stale gold fails loudly. I loaded the live index (version 34c67d0bba77, 235 docs, 4482 chunks) and confirmed that for all 34 gold rows `held_out_chunk_ids` and `held_out_ords` equal the document's current root_cause chunks. Held-out is the whole root_cause section, not just the first chunk.

2. Neighbor chunking does not leak. `NeighborChunking.patched_rows` (chunking.py:58-71) re-embeds every flat-adjacent same-document chunk of a held-out chunk using `context_text(..., skip)`, which omits the held-out text. The cached matrix is only used for rows whose context could not contain a held-out chunk. Contiguous and non-contiguous held-out sets (for example q016, ords 23-26 and 39) are handled because adjacency is per excluded index. Tests: test_context_text_leaves_out_held_out_neighbors, test_patched_rows_re_embed_only_neighbors_of_held_out_chunks_without_their_text, test_neighbor_retrieval_does_not_leak_the_held_out_chunk_through_neighbors.

3. Query wording. I read all 34 queries and compared each with its document. The generator filter (gold.py:100-114) rejects 5-word runs from the root-cause text and 8-word runs from the document. It also rejects source host names and the phrase "root cause". Per query, the content words that appear only in the root-cause text and not elsewhere in the document are almost all generic (across, small, instead, similar). I found no copied root-cause wording and no stated cause in any query. Residual hints are documented in build.md (q020, q032 mention remediation-adjacent symptoms). q010, q014 and q019 share a 3-gram with the root-cause text, but only common phrases.

Hand-checkable unit tests exist in tests/test_evals_metrics.py. I recomputed the metrics from the per-query ranks in all four result files, and they match the stored values and baseline.json exactly.
